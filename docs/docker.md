# Running Translation Management Platform with Docker on Windows

[Project overview and first-clone setup](../README.md#6-run-from-a-fresh-clone) · [Deployment configuration](deployment.md)

The root README contains the complete clone, configuration, migration, seed-account, and smoke-test walkthrough. This guide covers Docker-specific checks and troubleshooting. Run commands in PowerShell from the repository root.

## 1. Prerequisites and local configuration

Start Docker Desktop with Linux containers, and make PostgreSQL reachable from Docker. PostgreSQL is external to root Compose. You do not need .NET, Node.js, or Python on the host when using the Docker SDK migration option.

```powershell
docker version
docker compose version
Test-Path .\compose.yaml
powershell -ExecutionPolicy Bypass -File .\scripts\init-docker.ps1
```

The script preserves existing local JSON files and generates a RabbitMQ password when that setting is absent. New JSON files inherit empty credential fields from the tracked templates; successful initialization only means the files are ready to edit.

| File | Configure before use |
| --- | --- |
| `infra/docker/api.local.json` | A random JWT secret of at least 32 ASCII characters, the PostgreSQL connection string, and Azure Blob settings for file/package features |
| `infra/docker/email.local.json` | SendGrid API key, verified sender email, and sender name |
| `.env` | A nonempty `RABBITMQ_PASSWORD`, generated by the initialization script |

Keep the other template defaults unless needed for your environment. Compose overrides Redis, RabbitMQ, frontend/CORS, and the API's AI URL. It also sets the AI container's `OLLAMA_HOST` to `http://ollama:11434`.

Use `host.docker.internal` for PostgreSQL on Windows or a separate database container with a host-published port. `localhost` inside the API container refers to the API container itself.

The Email host validates SendGrid settings at startup. Leaving its API key empty prevents that host from starting; it is not a delivery-only error. The API can be tried independently with the verified seed accounts by omitting Email from startup.

## 2. Run database migration before startup

Follow [Step 4 of the root README](../README.md#step-4-create-the-database-and-seed-data) using either the Docker SDK image or .NET SDK 10 on the host. Both commands run `Sequences → Scripts → Functions → Alter → Seed`; no additional seed command is needed.

Continue only after the log reports `Migration SUCCESS for database: MySolution`. The migration runner currently logs failures without explicitly setting a failing process exit code, so check its output.

The same README section lists the seed accounts. Login uses `admin`, `translator1`, or `reviewer1` as the username, not the account's email address.

## 3. Verify local files and Compose

```powershell
git check-ignore .env infra/docker/api.local.json infra/docker/email.local.json
docker compose config --quiet
```

The ignore check should list all three files. Use `--quiet` to avoid printing expanded configuration values. Compose validation checks the configuration structure, not database credentials, schema state, or cloud connectivity.

## 4. Build and start

With all required settings configured:

```powershell
docker compose up -d --build
docker compose ps -a
docker compose exec ollama ollama pull qwen2.5:3b
```

Expected services: `web`, `api`, `email`, `redis`, `rabbitmq`, `ollama`, `ai-translation`, and `translation-read`. The model persists in the `ollama-data` volume across container restarts.

For a limited local trial without SendGrid, use this startup command instead:

```powershell
docker compose up -d --build redis rabbitmq api web ollama ai-translation translation-read
```

Use the verified seed accounts; new-account verification and password-reset email delivery are unavailable in this mode. Azure Blob is still required for Blob-dependent operations, including release packages.

## 6. Common problems

| Symptom | Check |
| --- | --- |
| API exits with a missing JWT secret | Set `Jwt:SecretKey` in `api.local.json`, then recreate the API container. |
| Database-backed requests fail | Check PostgreSQL is running and accessible from containers, the connection string uses the correct hostname, and migration finished successfully. |
| Email exits during options validation | Fill in all three required SendGrid settings, or use the limited startup command without Email. |
| A new user cannot log in | Complete email verification. Use a verified seed account to test without email delivery. |
| Upload, import/export, or package processing fails | Check Azure Blob connection/container settings and inspect API consumer logs. |
| AI responds but suggestions fail | Check `ollama list`, pull `qwen2.5:3b` if missing, and inspect `ai-translation` and `ollama` logs. |
| Translation Read gets an authorization error | Set the API URL, project ID, and Application API Key in `ApiConfigPanel`; grant the permission required by the selected request. |
| Demo cannot read the expected release | Publish a release for the same project associated with the Application API Key. |
| RabbitMQ rejects credentials after an `.env` change | The existing RabbitMQ user's password is stored in its volume. Changing the environment variable alone does not update that user. |

Inspect logs with:

```powershell
docker compose logs -f --tail 100 api email
docker compose logs --tail 100 ai-translation ollama
```

Press Ctrl+C to stop following logs. Omit `email` when running the limited setup.

## 7. Restart, rebuild, and stop

```powershell
# Apply changes to the mounted local JSON files or restart after migrations.
docker compose restart api email

# Apply changes to Compose environment variables.
docker compose up -d --force-recreate api email

# Rebuild after source changes.
docker compose up -d --build

# Stop containers, preserving named volumes.
docker compose down

# Start an already configured stack again.
docker compose up -d
```

When using the limited setup, omit `email` and retain the explicit service list when starting or rebuilding.

Only use `docker compose down -v` when you intend to remove the Redis, RabbitMQ, Ollama model, and Data Protection volumes. External PostgreSQL and Azure Blob data are not removed. Keep `.env` and both local JSON files private.
